# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Unattended Windows ETL job: logs into a corporate Spotfire portal with Selenium, downloads the "DDA" report (vehicles delivered by dealers to end customers) as Excel, filters it with pandas, and loads new VINs into SQL Server. Code, identifiers, log messages and docs are in Spanish — keep new code consistent with that.

## Commands

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requerimientos.txt
python main.py                  # runs the full pipeline (needs .env, portal access and SQL Server)
pyinstaller main.spec           # production build, deployed as a Windows scheduled task
```

The local `main.spec` (gitignored by `*.spec`) is a one-folder build (`COLLECT`, output in `dist/main/`) that bundles `.env` via `datas=[('.env', '.')]`. The README still says `pyinstaller --onefile main.py`; avoid that: it does not bundle `.env`, and in one-file mode `sys._MEIPASS` is a temp dir deleted on exit, so the log and download folder (resolved through `resource_path`) would vanish with it. In the one-folder build they live under `dist/main/_internal/`.

There are no tests, linter config, or CI. The only way to exercise the pipeline end-to-end is a real run against the portal and database.

`requerimientos.txt` is UTF-16 LE encoded (generated by `pip freeze >` in PowerShell). Preserve that encoding when editing it, or convert it deliberately.

## Architecture

Layered (MVC-ish) structure; each class reads its own config from environment variables via `os.getenv` in `__init__`, so `.env` must be loaded (done in `main.py`) before any class is instantiated.

Call flow:

1. `main.py` → `load_dotenv(resource_path(".env"))` → `crear_carpetas()` (creates the `ARCHIVO_LOG` parent dir and `DESCARGA_REPORTE` if missing) → `etl_dda_controlador.procesar_reporte_dda()`
2. `controlador/lectura_archivo_controlador.py` retries `ClienteSelenium.descargar_archivo_dda()` up to `INTENTOS_DESCARGA` times. That method returns a dict `{"estado": bool, "error"?: str}` instead of raising.
3. `infraestructura/cliente_selenium.py` drives Chrome: login (IPN → next → choose password → password → verify), then double-clicks through 7 folder XPaths (`_navegar_carpetas`), switches to the new window, and exports the report via context menu into `DESCARGA_REPORTE`. Uses `ChromeDriverManager`, falling back to the local `RUTA_WEBDRIVER`. Some XPaths are hardcoded absolute paths in the method body. The rest come from env vars. Pacing uses explicit `WebDriverWait`s only (no implicit wait, so don't add one: it would make the 3 s `validar_exitencia` check block for the full implicit timeout), `*_click_safe` retries on `StaleElementReferenceException`, and `_abrir_menu_tabla`, which repeats the first report click until the table responds. Each stage logs its elapsed seconds. After the export it polls `DESCARGA_REPORTE` (`_esperar_descarga`, up to `_WAIT_DOWNLOAD` s) until there is a complete file and no `.crdownload`/`.tmp`; partial files from earlier attempts are removed at the start.
4. `modelo/procesar_archivo.py` takes the **first file** found in the `DESCARGA_REPORTE` directory, keeps rows where `Process == "Delivery"` with columns `VIN`, `End_Date`, hands them to `InsertaDatos`, and **always deletes the file**, including when it is empty or unreadable, so the next run doesn't pick it up again.
5. `modelo/inserta_datos.py` connects with pyodbc (`ODBC Driver 17 for SQL Server`), bulk-inserts into `DATASTEWARD..reporte_dda_temp` (`fast_executemany` + `setinputsizes` from `typeToSize`), then `delta_data()` copies only VINs not already in `DATASTEWARD..reporte_dda` (`NOT EXISTS`, one row per VIN with `MAX(fecha_entrega)`, `GETDATE()` as `fecha_registro`) and empties the temp table. The temp table is also emptied before inserting, and everything is one transaction: any failure rolls back.

Cross-cutting:
- `servicios/resolver_rutas.resource_path` resolves paths against `sys._MEIPASS` when frozen by PyInstaller, else the CWD. Use it for every file path (`.env`, log, download dir, driver), and run from the repo root.
- `vista/logger.Logger` wraps `logging.basicConfig` writing to `ARCHIVO_LOG`. `main.py` brackets each run with `inicio_ejecucion()` (a blank line plus a header) and `fin_ejecucion(exito)`. When the run fails, before the end line, `infraestructura/cliente_correo.ClienteCorreo.enviar_alerta_fallo()` sends one email with `Logger.log_ejecucion_actual()` (the log lines since the last header) attached. A failed email is only logged and doesn't change the exit code. Errors are logged rather than raised. Each step returns a bool up to `main.py`, which exits with code 1 on failure (or on any unexpected exception, logged with its traceback) so the Task Scheduler history shows it. Check the log file for the cause.

Gotchas:
- `DESCARGA_REPORTE` must hold only the downloaded report. `listar_archivos` picks the first file `os.listdir` returns, so any leftover file (for example a partial `.crdownload`) gets read and then deleted. If the folder is empty it returns `None`, which is logged as an error.
- The temp-table insert is positional (`VALUES (?,?)`), so the DataFrame column order `VIN, End_Date` must match the column order of `reporte_dda_temp` (`vin, fecha_entrega`).
- Behind the corporate proxy without `PROXY_HOST`, `ChromeDriverManager().install()` times out (`WinError 10060`) before it falls back to `RUTA_WEBDRIVER`. Even with the proxy set, keep a chromedriver that matches the installed Chrome version at that path.

## Configuration (.env)

The README has a full `.env` template. Variables read by the code:

- General: `INTENTOS_DESCARGA`, `DESCARGA_REPORTE` (download dir, e.g. `Recursos`), `ARCHIVO_LOG` (e.g. `Log/log.txt`), `RUTA_WEBDRIVER`, `PROXY_HOST` (optional `host:port`; the chromedriver download goes through it with `IPN`/`CLAVE`, set via `HTTPS_PROXY` only while it runs, because Selenium also reads that variable), `MODO_OCULTO` (`"True"` runs Chrome headless at 1920x1080 and allows downloads via CDP `Browser.setDownloadBehavior`, so the scheduled task can run with no user logged on)
- Portal: `RUTA_SPOTFIRE`, `IPN`, `CLAVE`, `ID_INPUT_IPN`, `ID_INPUT_CLAVE`, `XPATH_SIGUIENTE`, `XPATH_INGRESAR_CLAVE`, `XPATH_VERIFICAR`
- Folder XPaths: `XPATH_CARPETA_DA3`, `XPATH_CARPETA_DESING`, `XPATH_CARPETA_COL`, `XPATH_CARPETA_REPORTS`, `XPATH_REPORTS_IN_PROGRES`, `XPATH_CARPETA_DDA`, `XPATH_CARP_COL_DS_DDA_COLOMBIA`
- SQL Server: `SERVIDOR_SQL`, `USUARIO_SQL`, `CONTRASENA_SQL`, `BD_DATASTEWARD`
- Failure email: `CORREO_REMITENTE`, `SERVIDOR_SMTP`, `PUERTO_SERVIDOR_SMTP` (plain SMTP relay, no login, no TLS), `DESTINATARIO` (comma-separated list)

The `Log/` and `Recursos/` folders are not in git; `main.py` creates them at startup.
